# Единый реестр университетов

Этот этап добавляет в проект основу центрального реестра вузов и филиалов. Он **не загружает автоматически сведения о льготах и не подтверждает правила приёма**: на первом этапе импортируются организации, официальные домены и ссылки на страницы приёмной кампании, правил и мест.

## Источники

| Источник | Роль в реестре | Интеграция на этом этапе |
|---|---|---|
| Минобрнауки: https://minobrnauki.gov.ru/abitur/ | Каталог организаций и ссылки на страницы приёма, правила и количество мест | Автоматический импорт HTML-каталога с пагинацией |
| Мониторинг высшего образования: https://monitoring.miccedu.ru/?m=vpo | Организации, филиалы, регион и профиль мониторинга | Автоматический импорт региональных списков и ссылок на карточки организаций |
| Рособрнадзор: https://obrnadzor.gov.ru/ | Проверка лицензий и государственной аккредитации | Источник зарегистрирован в справочнике, ручная проверка; публичный массовый формат выгрузки пока не подтверждён |
| Госуслуги: https://www.gosuslugi.ru/vuznavigator | Дополнительная сверка вузов и программ | Справочный источник; публичный массовый API не подтверждён |

У источников разная полнота и периодичность. Мониторинг MICCEDU 2025 относится к статистическим данным за 2024 год; это не правила приёма на 2025 или 2026 год. Нельзя трактовать присутствие в статистическом мониторинге как подтверждение действующей лицензии или текущих правил приёма.

## Новые таблицы Supabase

- `university_registry_sources` — каталог источников и уровень интеграции.
- `university_registry_import_runs` — журнал каждого запуска импорта, статистика и ошибки.
- `university_registry_records` — исходные записи из внешних реестров и результат сопоставления.
- `university_external_ids` — связь внутреннего вуза с идентификаторами государственных источников.
- `university_official_domains` — домены и страницы, на которых основана связь с вузом.

Существующая `public.universities` расширена полями региона, адреса, домена, ИНН/ОГРН, типа организации, признака филиала и официальных ссылок. Таблицы `programs` и `benefits` не удаляются и их структура на этом этапе не меняется.

Реестровые таблицы закрыты RLS для `anon` и `authenticated`. Их может читать/менять только серверный импортёр через Supabase Secret/Service Role key. Никогда не помещайте этот ключ во frontend, Vercel или GitHub.

## Установка

### 1. Применить SQL-миграции

Если реестр ещё не создавался, сначала примените `backend/supabase/migrations/202611230001_university_registry.sql`.

Затем обязательно примените новую миграцию `backend/supabase/migrations/202611230003_registry_profile_enrichment.sql`. Она добавляет адрес организации и статус домена `listed_by_miccedu`, не удаляя существующие записи. Если миграция `202611230001` уже была применена, повторно запускать её не нужно.

### 2. Подготовить локальный секрет для импортёра

Импорт запускается только локально из корня проекта. Создайте локальный файл:

```powershell
Copy-Item backend/.env.example backend/.env
notepad backend/.env
```

Заполните в `backend/.env` только необходимые для импорта значения:

```env
SUPABASE_URL=https://YOUR_PROJECT.supabase.co
SUPABASE_SECRET_KEY=YOUR_SUPABASE_SECRET_KEY
```

В актуальных проектах Supabase используйте Secret API key (обычно начинается с `sb_secret_`). Для старых проектов поддерживается `SUPABASE_SERVICE_ROLE_KEY`. Ключ берите в настройках API вашего Supabase-проекта. Не отправляйте его в чат и не добавляйте в Git.

`backend/.env` исключён из Git через `.gitignore`. После создания проверьте:

```powershell
git status --short
```

Файл `backend/.env` не должен появляться среди изменений.

### 3. Сначала выполните безопасный dry-run

Проверить доступность страниц и качество парсинга, не записывая данные в Supabase:

```powershell
npm.cmd run registry:import -- --source=all --dry-run
```

Если нужно проверить только первые две страницы Минобрнауки:

```powershell
npm.cmd run registry:import -- --source=minobrnauki --minobrnauki-pages=2 --dry-run
```

Проверить только первые два региона MICCEDU и обогатить максимум пять индивидуальных карточек:

```powershell
npm.cmd run registry:import -- --source=miccedu --max-regions=2 --miccedu-profile-limit=5 --dry-run
```

По умолчанию импортёр загружает профильную карточку каждой найденной организации MICCEDU. Из карточки извлекаются полный адрес, город, регион, официальный сайт с сохранением точного поддомена (важно для филиалов), ведомственная принадлежность и ссылка на головную организацию только из специального поля карточки. Случайные навигационные ссылки не используются для определения головного вуза. Короткое название филиала формируется из его локального названия, без длинного юридического названия головной организации. Между запросами выдерживается пауза, а ошибки отдельных профилей фиксируются без потери остальных записей.

Некоторые страницы государственных сайтов могут быть временно недоступны, отдавать защитную страницу или менять HTML. Импортёр фиксирует ошибки, пропускает отдельные страницы и продолжает обработку; если первая страница источника не распознана, импорт останавливается, чтобы не записать пустой каталог.

### 4. После успешного dry-run запишите данные

Полный импорт двух активных каталогов:

```powershell
npm.cmd run registry:import -- --source=all
```

Или источники по отдельности:

```powershell
npm.cmd run registry:import -- --source=minobrnauki
npm.cmd run registry:import -- --source=miccedu
```

Параметры:

- `--source=all|minobrnauki|miccedu`
- `--minobrnauki-pages=2` — ограничение количества страниц Минобрнауки для тестового запуска.
- `--miccedu-year=2025` — год выпуска мониторинга MICCEDU. Для него `data_year` сохраняется как `2024`.
- `--max-regions=2` — ограничение числа региональных страниц MICCEDU.
- `--miccedu-profile-limit=5` — ограничение числа индивидуальных карточек MICCEDU для тестовой загрузки.
- `--dry-run` — запрет записи в Supabase.

Не запускайте полный импорт многократно без необходимости. Повторные строки сопоставляются сначала по ИНН/ОГРН, затем по официальному домену с учётом признака филиала, затем по нормализованному названию и региону. Неоднозначные совпадения помещаются в `match_status='review'`, а не объединяются автоматически. Профиль MICCEDU обогащает ранее созданные записи: заполняет неизвестный город и адрес, уточняет регион, сохраняет точный официальный hostname (включая поддомены филиалов) и связывает филиал с головной организацией только при наличии явной ссылки в соответствующем поле карточки. Короткие названия очищаются от юридических префиксов; для филиала сохраняется его локальное имя, а не длинное юридическое название головного вуза. Явно заполненные вручную города и качественные короткие названия не перезаписываются; исправляются только пустые/служебные значения и явно обрезанные или юридически загрязнённые короткие названия. Повторный запуск того же импорта обновляет существующие строки по внешнему идентификатору MICCEDU и не создаёт новую запись для той же карточки источника.

## Как читать статусы

`universities.registry_status`:

- `minobrnauki_listed` — найдено в каталоге Минобрнауки;
- `miccedu_listed` — найдено в мониторинге MICCEDU;
- `multiple_sources` — найдено в обоих источниках;
- `manual` — добавлено ранее вручную;
- `needs_review` — требует отдельной ручной проверки.

`university_registry_records.match_status`:

- `created` — создана запись университета;
- `matched` — запись источника сопоставлена с уже существующим вузом;
- `review` — автоматическое сопоставление неоднозначно;
- `pending` — ещё не обработана;
- `rejected` — отклонена после ручной проверки.

Само присутствие в каталоге не означает, что официальный сайт, лицензия, аккредитация или приёмная кампания подтверждены полностью. Домен из каталога Минобрнауки помечается `listed_by_ministry`, а домен из индивидуальной карточки MICCEDU — `listed_by_miccedu`; ни один из этих статусов не равен ручному подтверждению `verified`.

## Что будет в следующих этапах

1. Дополнительно обогатить карточки MICCEDU: получить город, сайт организации и идентификаторы из индивидуальных страниц.
2. Найти официальные страницы программ, правила приёма и документы по годам 2027 и 2026.
3. Извлекать БВИ, 100 баллов, дополнительные баллы и сводные требования с сохранением фрагментов-доказательств.
4. Показывать в сравнении только подтверждённые факты; неизвестное обозначать как «нет подтверждённых данных».

Исторические данные разных лет будут храниться отдельно. Правила и льготы предыдущего года нельзя автоматически переносить на новую кампанию.
