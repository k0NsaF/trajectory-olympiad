# Trajectory V2 — статус поставки исходного проекта

**Состояние на 25 ноября 2026 года**
Это обновлённый исходный проект, а не production-развёртывание. Настройки API, секреты и живые изменения Supabase отложены до совместного финального шага.

## Реализовано в коде

- Единая светлая оболочка с логотипом-ссылкой слева, горизонтальным меню и входом/регистрацией справа.
- Восстановлены семь карточек входа на главной: пять в первом ряду и две во втором.
- Убрана отдельная страница и API старой «Моей траектории». Сохранены профиль, достижения, календарь, сравнения и AI-помощник.
- Возвращён календарь в меню и маршруты; выбор олимпиад синхронизируется с календарём. Календарь загружает все выбранные мероприятия, а не только совпавшие с фильтрами анкеты.
- Созданы отдельное избранное для олимпиад/университетов и хранение по гостевой/пользовательской области в браузере.
- Каталог вузов: поиск, город, регион, тип организации, филиалы, сортировка, список с фотографическим слотом слева, страница деталей, источники данных и сравнение ниже каталога. Добавить в сравнение можно из полной страницы вуза.
- Отображение университетского фото требует одновременно URL изображения, страницы-источника и основания лицензии/разрешения. Без этого выводится нейтральная заглушка.
- Каталог олимпиад: отдельные вкладки двух перечней, фильтры, детали, избранное и добавление в календарь. Числовой рейтинг не выдумывается: в текущей БД поля рейтинга нет; сортировка опирается на статус сверки, уровень и название.
- AI-контекст учитывает страницу, анкету, выбранные университеты/мероприятия; переход на раздел выполняется только при явной просьбе пользователя. Источники свёрнуты по умолчанию.
- История диалога и гостевые избранные элементы хранятся локально в браузере с разделением по пользователю. Без синхронизации на сервере данные не переносятся автоматически между устройствами.
- В пароле добавлена кнопка показа/скрытия, исправлен переход после входа/регистрации; поля имеют явные стили фокуса, контрастный текст и активный ввод.
- При входе гостевые избранные олимпиады/вузы и выбранные олимпиады календаря объединяются с локальными данными аккаунта без потери уже сохранённых записей.
- Добавлена SQL-миграция с годовыми атрибутами официального перечня и метаданными фотографий университетов; проверка не допускает уровень у записи второго перечня и не позволяет привязать новую/изменённую льготу ко второму перечню. Миграция лежит в репозитории и пока НЕ применялась к живой базе.

## Что намеренно не активировано

- Не настроены `VITE_API_URL`, Supabase URL/Publishable Key, ключ Groq, Cloudflare, Tavily и другие реальные секреты.
- Не применялась новая миграция к production Supabase и не менялись живые данные.
- Не импортированы все 60 записей приказа Минобрнауки № 521 и полный перечень Минпросвещения № 598; старые записи показываются как требующие проверки до ручной сверки.
- Не загружены фотографии 1040 университетов: схема и интерфейс готовы, но каждое изображение нуждается в проверяемом источнике и лицензии/разрешении. Заглушки намеренные.
- Автоматическая доставка push/email/MAX не настроена. Календарь хранит время напоминания, но не притворяется, что уведомление уже отправлено.
- Вход через MAX — будущий адаптер после получения требований и официальной документации.
- Полная облачная синхронизация избранного и истории AI требует отдельной схемы пользовательских таблиц и правил RLS; пока применяется localStorage.
- Оценка «какой вуз лучше для пользователя» пока выполняется как объяснимое AI-сопоставление характеристик в диалоге, а не как числовой график или статистически проверенная вероятность поступления. Для графика сначала нужны заполненные и сопоставимые данные по программам, экзаменам, местам и локальным правилам.

## Данные Supabase, прочитанные без изменений

Подключённый проект `trajectory-olympiad` был доступен в статусе `ACTIVE_HEALTHY`. Во время аудита прочитаны только схема, миграции и advisory notices. На момент чтения: 1 040 университетов, 42 программы, 15 олимпиад, 13 сезонов, 26 этапов, 36 строк льгот, 4 профиля и 3 достижения.

Дополнительно advisory notices указывали на 5 таблиц реестра вузов с включённым RLS без policies, публичную возможность исполнения `public.handle_new_auth_user()` как SECURITY DEFINER и отключённую проверку скомпрометированных паролей. Эти вопросы нужно решить на финальном этапе конфигурации Supabase после проверки фактических прав доступа и триггеров. Они не изменялись в рамках подготовки ZIP.

Список удалённых миграций на удалённом проекте вернулся пустым, хотя таблицы и данные присутствуют. Перед первой отправкой DDL нужно отдельно сверить историю миграций и фактическую схему; нельзя просто «применить всё подряд».

## Проверки в этой среде

- Архив исходника распакован и его структура просмотрена.
- Проведена проверка маршрутов и относительных импортов после переработки.
- TypeScript/TSX проверены на синтаксический разбор через TypeScript compiler API.
- Запущены доступные Node.js parser tests.
- `npm run typecheck --workspace=shared` — пройден.
- `node --test backend/tests/university-registry-parser.test.mjs` — пройдено 12/12 тестов.
- TypeScript/TSX всех исходников прошли синтаксический разбор, относительные импорты и локальные публичные ассеты проверены отдельными скриптами.
- Полный backend/frontend `typecheck` и production `build` нельзя подтвердить в этой среде: архив не содержит `node_modules`, npm-кэш пуст, а восстановление зависимостей завершилось сетевым тайм-аутом. Поэтому они должны быть запущены локально командами ниже.
- Браузерная визуальная проверка реального рендеринга не выполнялась в этой среде. После установки зависимостей нужно проверить десктоп и мобильный viewport.

## Финальный порядок запуска

1. Локально установить зависимости и пройти typecheck/build/tests.
2. Взять резервную копию Supabase и сверить таблицы/RLS/триггеры с репозиторием.
3. Проверить и применить миграцию `202611250001_official_lists_and_university_media.sql` только после review; затем выполнить read-only запросы из `backend/supabase/verification/202611250001_official_lists_and_media.sql`.
4. Импортировать и сверить официальные списки и локальные акты вузов.
5. Собрать verified photo sources для университетов.
6. Вместе заполнить API settings и секреты только в соответствующих backend hosting settings / локальных `.env`, никогда во frontend bundle или Git.
7. Проверить регистрацию, пароль, каталог, избранное, календарь, напоминания, AI и CORS на тестовом окружении.
